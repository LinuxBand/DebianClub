Content freshness marks pages whose facts change over time, preventing release dates, lifecycle windows, cloud image build IDs, Docker tags, package support, and deployment instructions from drifting.

## Phase 44 Live

The release gate now includes:

```bash
corepack pnpm --dir web freshness:check
corepack pnpm --dir web facts:check
```

`freshness:check` reads the review baseline from `web/lib/debian-facts.json` and verifies that key pages still contain the current review date, official source links, and lifecycle dates that must stay synchronized. `facts:check` cross-checks the fact source against Debian's official Release files and all 8 localized pages.

## Update Flow

1. Check official sources first; do not copy lifecycle dates from summaries.
2. Run `corepack pnpm --dir web facts:sync` to refresh `web/lib/debian-facts.json` from Debian's official Release files, cloud image metadata, and Docker Hub tags (the committed cache is kept when the network is unavailable).
3. Update the version-sensitive pages (`versions`, `eol`, `news`, `whats-new`, `download`, `bootable-media`, `server/cloud`) with the new versions, dates, and image build IDs.
4. Run `corepack pnpm --dir web freshness:check`.
5. Run `corepack pnpm --dir web facts:check` to confirm the fact source and pages agree.
6. Run the full `corepack pnpm --dir web release:check`.

## When The Check Fails

Do not loosen the check immediately. First determine:

- Whether the mandatory review date has arrived.
- Whether Debian official sources changed lifecycle or release-note information.
- Whether a page is missing official source links.
- Whether only one of the Chinese or English pages was updated.
